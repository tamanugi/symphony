Symphony Project Structure

Symphony is a service specification and reference implementation for orchestrating autonomous coding-agent work from issue trackers into isolated workspaces.

Repository role Service spec plus reference app
Primary implementation Elixir / OTP / Phoenix
Main quality gate make all in elixir/

Recommended Reading Order

  • README.md explains what Symphony is and points to the reference implementation.
  • SPEC.md defines the portable orchestration model and required behavior.
  • elixir/README.md describes setup, configuration, adapters, releases, and operation.
  • elixir/AGENTS.md captures implementation rules, validation, and PR requirements.
  • elixir/WORKFLOW.md provides a sample tracker workflow used by Symphony runs.

Key Project Areas

SPEC.md

Defines Symphony as a language-agnostic scheduler, workspace manager, tracker adapter layer, agent runner, and observability surface.

docs/

Holds smoke-test and review notes used to exercise the orchestration workflow without changing application behavior.

.github/

Contains pull request requirements, media used by documentation, CI, PR description linting, and Burrito release automation.

.codex/skills/

Stores local agent skills for Linear updates, commits, pushes, branch syncing, release handling, and PR landing flows.

elixir/

Implements the reference Symphony service with Mix, Phoenix, tracker adapters, workspace orchestration, and release tooling.

elixir/test/

Covers core orchestration, adapters, status dashboard snapshots, CLI behavior, workspace/config handling, and live e2e flows.

Elixir Implementation Map

Path Purpose
elixir/lib/symphony_elixir/ Core orchestration, config, workflow parsing, workspace safety, logging, agent runtime supervision, and CLI code.
elixir/lib/symphony_elixir/*/adapter.ex Tracker adapters for Linear, GitHub Issues, Jira, Asana, and GitLab.
elixir/lib/symphony_elixir/codex/ Codex app-server and dynamic tool integration used by agent sessions.
elixir/lib/symphony_elixir_web/ Phoenix endpoint, router, LiveView dashboard, observability API, presenters, and static asset serving.
elixir/lib/mix/tasks/ Project-specific Mix tasks for spec checks, PR body validation, and workspace cleanup hooks.
elixir/config/ Application configuration for runtime services and the optional Phoenix surface.
elixir/priv/static/ Static dashboard assets served by the Phoenix web layer.
elixir/test/support/ Shared test helpers plus Docker support for live end-to-end validation.

Development And Validation

  • Install dependencies from elixir/ with mix setup.
  • Run the main local quality gate from elixir/ with make all.
  • Run spec coverage checks with mix specs.check.
  • Validate pull request descriptions with mix pr_body.check --file /path/to/pr_body.md.
  • Keep behavior and configuration documentation aligned with SPEC.md, README.md, and elixir/README.md.
